BLIXEL: MAKING EXISTING FEATURES SOLID

Requirements for an AI coding agent. This file says how to make Blixel's existing features reliable: three foundations and twenty features. It adds no features; build nothing outside that list unless the user asks. Evidence dates from 6 October 2026.

Reading the evidence:
- IDs (S1-S7, G1-G9, R1-R67) are findings in "Blixel feature gaps and user requests".
- "129/15" is upvotes/comments. "n/r" is not readable. "HN" is Hacker News; its figures are thread points/comments, not votes for the quoted remark.
- [strong] several independent sources or high counts. [thin] one or two sources, or second-hand. [practice] no direct evidence; needed for the feature to function.
- Tags measure evidence, not priority. A protocol or security requirement from one primary document is [thin] and still binding.


CORRECTIONS TO EARLIER ASSUMPTIONS

1. Agent edits do not arrive through the host.
- The Agent Client Protocol (ACP) version 2 draft removes the file-system methods a host used to see agent writes (per a Zed maintainer; not in the announcement as read). https://github.com/zed-industries/zed/discussions/56048
- Build: detect edits by watching each agent's working copy, or by diffing against a snapshot taken before each turn.

2. ACP v1 and v2 run side by side.
- v2 is a draft (20 July 2026) with no stabilisation date; hosts are told to support both. https://agentclientprotocol.com/announcements/acp-v2-draft.md
- v2 changes: session updates at any time; stable, patched message IDs; structured file changes (add, delete, modify, move, copy); permission requests with required titles and descriptions, decoupled from tool calls.

3. The Model Context Protocol (MCP) is stateless.
- The 28 July 2026 specification removes sessions and the initialize handshake, and deprecates Roots, Sampling and Logging (minimum twelve months). https://blog.modelcontextprotocol.io/posts/2026-07-28/
- Build: Blixel's MCP server and connector client target it; no deprecated feature.

4. The Claude Code and Codex adapters lag and have open defects.
- Both reach ACP only through adapters. https://agentclientprotocol.com/overview/agents
- claude-agent-acp: 68 open issues, including a permission request sent in bypass mode (#1196), a usage update reporting 200k for a 1M-context session (#1181), and MCP servers needing sign-in skipped (#1183). https://github.com/agentclientprotocol/claude-agent-acp/issues
- Zed's codex-acp was archived 22 July 2026; its move is pending. https://github.com/zed-industries/codex-acp/issues
- Build: treat adapter output as fallible (Foundation A).

5. "The same files" and "a working copy per agent" conflict.
- A working copy per agent isolates files; a shared editor shows agents together. Only Solo shares one checkout, with lease-based locks. https://soloterm.com/agents
- Build: every buffer states which working copy it shows.

6. An agent's own report is not status.
- Agents report "fixed" after merely suppressing the error (R7; 6 sources). https://news.ycombinator.com/item?id=47602986
- Build: status, logs and "done" come from what Blixel observed.

7. Rollback cannot be left to the agent.
- ACP carries no checkpoint restore; Claude Code's checkpoints skip shell-command changes (R3). https://code.claude.com/docs/en/checkpointing


FOUNDATION A. HOSTING AGENTS OVER ACP

What goes wrong elsewhere
- Adapter defects and the archived Codex adapter: Correction 4.
- Wrapping the Claude Code terminal program "became unfeasible to maintain" (Omnara; second-hand). https://feedbagel.com/post/omnara-a-mobile-platform-for-managing-and-communicating-with-ai-agents
- A bundled agent kit crashes on Windows (Nimbalyst #1361, n/r). https://github.com/nimbalyst/nimbalyst/issues
- Parallel subagents exhaust memory; runs end on transient errors (Claude Code #70523, #70475, n/r). https://claudeissues.com/digest/2026-06-24
- A host "wouldn't release file descriptors" (Conductor; one HN comment, 279/164). https://news.ycombinator.com/item?id=47866750
- Host profiles and skills do not apply to external agents; users file requests for native features lost over ACP (R4, R45, R61). https://zed.dev/docs/ai/external-agents

Solid means
- Blixel negotiates v1 or v2 per agent; every criterion here passes under both. [thin]
- Each adapter's version is pinned, shown, and never updated silently. [strong]
- One agent's crash, hang or failed start leaves Blixel and other agents running. [thin]
- Removing an agent or quitting ends its child processes and file watchers; open file handles return to baseline. [thin]
- Where an adapter lacks something Blixel relies on, that agent's page says so; no control does nothing. [strong]

Constraints
- ACP does not standardise subagent activity (R26; discussion #690, 13/4). https://github.com/agentclientprotocol/agent-client-protocol/discussions/690


FOUNDATION B. FIRST-RUN SETUP

What goes wrong elsewhere
- Every agent needs its own install and login; the login is the main friction. https://github.com/pingdotgg/t3code
- Claude Code open/total issues: Windows and Windows Subsystem for Linux 3,121/19,373; authentication 1,824/11,482; installation 535/4,387 (R52; mirror; problem counts, not votes). https://claudeissues.com/topic
- Docker, the command line and antivirus flagging unsigned executables block users (R57; Odysseus #636, 10 upvotes). https://github.com/odysseus-dev/odysseus/discussions/636

Solid means
- With no Node.js and no agent installed, the user installs and starts Claude Code, Codex and OpenCode inside Blixel without a terminal. [strong]
- Each agent shows "signed in" or "needs sign-in"; sign-in runs the agent's own flow. [strong]
- API (application programming interface) keys live in the operating system's credential store, never in project files, chat or logs. [thin]
- A failed setup step names the step and cause, and does not block other agents. [strong]
- Installers are code-signed on every operating system Blixel ships for. [thin]

Constraints
- Agent sign-in is unavoidable: billing is between user and provider (R51). https://zed.dev/docs/ai/external-agents
- Reference pattern: the host downloads the agent and manages Node.js or Python runtimes. https://www.jetbrains.com/help/ai-assistant/acp.html


FOUNDATION C. SECURITY

What goes wrong elsewhere
- A prompt injection made one coding agent rewrite another's configuration to lift its restrictions (research demonstration; second-hand; September 2025, possibly outdated). https://simonwillison.net/2025/Sep/24/cross-agent-privilege-escalation
- Self-propagating instructions reached about 55% infection through shared files such as AGENTS.md, about 17% by persuasion alone (G8; second-hand). https://codex.danielvaughan.com/2026/08/27/mind-viruses-self-propagating-instructions-multi-agent-llm-codex-cli-security/
- Users approve 97% of permission prompts, so a prompt alone is no safeguard (second-hand). https://gigazine.net/gsc_news/en/20260810-claude-code-auto-mode/
- An agent re-enabled tools the user had disabled (R15; Odysseus #5523, #5527). https://github.com/odysseus-dev/odysseus/labels/p1
- "Claude once bypassed the deny list and nuked an important directory" (HN 189/131). https://news.ycombinator.com/item?id=47218318
- No public incident in a commercial multi-agent coding workspace was found.

Solid means
- No tool call, shell command, connector call or agent message can change any agent's permissions, limits or "working with others" settings; only the user can. [strong]
- An agent's write to any agent's configuration, hook or instruction file (AGENTS.md, CLAUDE.md) is detected, attributed and held for the user's approval before it merges or reaches another agent. [strong]
- A message or hand-off from an agent never counts as user input, consent, or an answer to a permission request. [strong]
- A hand-off carries no permissions; the receiver acts under its own settings. [thin]
- Every command, tool call, connector call, permission decision and agent message is logged per agent. [thin]
- Secrets never appear in text sent to an agent (R67). [thin]

Constraints
- Sandboxing is out of scope, so the second criterion is detection, not prevention; worktrees are not a security boundary. https://code.visualstudio.com/docs/copilot/agents/overview

FEATURE 3. PERMISSIONS

What goes wrong elsewhere
- Allow rules are ignored: two open bugs, 27 and 26 comments (R9; Claude Code). https://claudeissues.com/issue/3673-feature-request-persistent-global-permissions
- Suggested "always allow" patterns are too narrow to stop repeat prompts (R9; Claude Code #83406, n/r). https://claudeissues.com/issue/83406-feature-suggested-always-allow-permission-patterns-are-often-too-narrow-to-preve
- Requests "are auto-denied without ever being shown to the user" (R21; Nimbalyst #1348, n/r). https://github.com/nimbalyst/nimbalyst/issues
- No single source of truth for external-agent permissions (R10; Zed #49590, 22/5); the exact command is not shown (R11; Zed #53879, 57/13). https://github.com/zed-industries/zed/discussions?discussions_q=is%3Aopen+sort%3Atop+ACP+agent
- Changing approval mode needs a restart (R15; Odysseus #6305, n/r). https://github.com/odysseus-dev/odysseus/issues/6305

Solid means
- Blixel answers every request from its own per-agent settings, whatever mode the agent reports. [strong]
- Every request under Ask reaches the user, subagent requests included; none is auto-denied or dropped unseen. [thin]
- "Always allow" sets that tool or connector to Allow for that agent, persists across restarts, and never prompts again; the prompt states this scope. [strong]
- Off holds through the shell (Foundation C): with push Off, a push typed in the agent's shell fails. Where Blixel cannot enforce this, the setting says so. [thin]
- A request shows the full command and working directory, plus the v2 title and description where supplied. [thin]
- A permission change applies to the running agent without restarting Blixel. [thin]
- A connector set to Off is not passed to that agent's session. [thin]

Constraints
- Evidence is single-agent; several agents prompting at once is an extrapolation.


FEATURE 4. SHARED CODE EDITOR

What goes wrong elsewhere
- "When agent updates file, it doesn't even register in the 'buffer'" (R43; one HN comment, 279/164). https://news.ycombinator.com/item?id=47866750
- Agents silently overwrite each other's work on shared state (one user, two HN threads). https://news.ycombinator.com/item?id=46993479
- Agent tooling does not track changes made by shell commands or most subagents. https://code.claude.com/docs/en/checkpointing
- No demand was measured for agent cursors, following or slowed typing; slowed typing is untested either way (G3).

Solid means
- An agent's write appears in an open buffer without reopening the file, however it was made. [thin]
- Replay is display only: the file on disk holds what the agent wrote, and the buffer equals it when replay ends. [practice]
- Status, diff, checkpoints and merge read the disk and never wait for replay; typing speed (2 to 40 characters per second, default 12) never slows the agent. [practice]
- Every buffer states its working copy and branch (R37). [strong]
- No edit is silently lost: when two parties change the same lines of one copy, both versions are kept and the conflict is shown. [thin]
- Moves and deletions update tabs and the file list. [thin]
- Line marks, cursors and the per-file agent list derive from detected changes and match the working-copy diff. [practice]

Constraints
- Corrections 1 and 5.

FEATURE 7. AGENTS WORKING TOGETHER

What goes wrong elsewhere
- Messaging between sessions drew 84 comments and at least seven duplicates; shipped for Claude sessions only (R23). https://claudeissues.com/issue/24798-inter-session-communication-for-multi-claude-workflows
- Background agents drop queued messages (R29; Claude Code, 14 comments in a week). https://claudeissues.com/digest/week/2026-07-13
- Agent teams "finish Claude tokens quota in 3 minutes, largely over delegation and result messages" (R30; HN 396/224). https://news.ycombinator.com/item?id=46902368
- An automatic review gate can loop two vendors' agents and drain usage limits. https://github.com/openai/codex-plugin-cc
- A cross-vendor hand-off keeps the transcript but loses the reasoning (R31; HN 72/28). https://news.ycombinator.com/item?id=47836740

Solid means
- The receiver is told each message came from a named agent, not the user. [strong]
- Blixel fixes sender identity when it passes the server to a session; no agent can send as another. [thin]
- The "working with others" settings are enforced by the server; a disallowed call fails with a reason. [thin]
- A message to a busy agent is queued and delivered at its next turn; the sender learns delivered or failed. [thin]
- Senders are rate-limited, repeats dropped, queues capped; automatic exchanges stop after a set number of turns. [thin]
- Messages and hand-offs appear in both agents' chats; a hand-off shows the original task and its origin. [thin]
- At session start Blixel checks the agent sees the server's tools; if not, the feature shows as unavailable. [thin]
- Message and hand-off tokens count toward the sender's usage and daily limit. [thin]

Constraints
- Baseline rules: Claude Code's documented ones. https://code.claude.com/docs/en/cross-session-messaging
- Correction 3: the server has no session to hold identity or queues, and no Sampling.

FEATURE 10. SOURCE CONTROL

What goes wrong elsewhere
- "Code needs to be reviewed BEFORE making destructive changes, not after" (R1; Codex #2998, 87 votes, February 2026 snapshot; 100+ comments). https://github.com/openai/codex/issues/2998
- Accept or reject of agent edits requested four times on Zed (R1; 30/7, 23/0, 23/2, 20/4). https://github.com/zed-industries/zed/discussions?discussions_q=is%3Aopen+sort%3Atop+ACP+agent
- "Git repository wiped after workspace deletion" (R39; Vibe Kanban #3406, n/r). https://github.com/BloopAI/vibe-kanban/issues
- Worktree creation writes an absolute path into configuration (R39; Claude Code #88747, 18 comments). https://claudeissues.com/digest/week/2026-08-17

Solid means
- One agent, one branch, one working copy; none shared (S1). [strong]
- Nothing reaches the user's branch without the user: the diff comes first, and each file is accepted or rejected. [strong]
- The diff is computed from the working copy, so it includes shell-command and subagent changes. [thin]
- The diff names its comparison branch: the agent's base branch unless the user picks another. [thin]
- Deleting a working copy never changes the main repository; Blixel snapshots it first and offers to delete the branch. [strong]
- Creating a working copy writes no absolute path into repository configuration. [thin]
- A conflicting merge is never completed or resolved silently; conflicting files are listed. [strong]

FEATURE 18. HISTORY WITH CHECKPOINTS

What goes wrong elsewhere
- "How is there not a /rewind or /revert feature?" (R3; Codex, 146/50). https://github.com/openai/codex/discussions?discussions_q=is%3Aopen+sort%3Atop
- Rewind is lost when Claude Code is hosted over ACP (R3; Zed #50192, 41/9). https://github.com/zed-industries/zed/discussions?discussions_q=is%3Aopen+sort%3Atop+ACP+agent

Solid means
- Blixel checkpoints an agent's working copy before each of its turns, for every hosted agent. [strong]
